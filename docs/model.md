# 生成模型

本仓库实现了一套可复现的程序化生态区域生成与演化系统。世界由大量相邻
区块（chunk）拼成，气候、水源与植被会跨越区块接缝相互传播。整个系统的
设计围绕四个核心性质：**可复现、边界连续、增量一致、并发安全**。

## 1. 确定性基础

所有地形值都是种子 `seed` 与世界坐标 `(x, z)` 的纯函数，不依赖任何全局
随机状态：

- 哈希函数 `hash2(seed, x, z, salt)` 基于 splitmix64 最终化，把整数坐标
  映射成 64 位随机数（见 `noise.py`）。
- 值噪声 `value_noise` 在四个哈希角点之间做双线性插值，得到 `[0,1]` 的
  平滑噪声。
- 分形布朗运动 `fbm` 叠加多个倍频，生成地形高度场。

因此，同一份种子与参数下，任意次生成得到的地形、气候与植被分布逐格一致，
与生成顺序、线程调度、调用时机均无关。

## 2. 单元与区块

- 一个**世界**（`World`）由若干**区块**（`Chunk`）组成，区块是不可变值
  对象。每个区块包含 `size * size` 个**单元**（`Cell`）。
- 单元字段：
  - `height`：地形高度（0..1），仅由种子决定；
  - `temperature`：温度（°C），基线由纬度、海拔与气候噪声决定；
  - `moisture`：湿度（0..1），海洋为 1.0；
  - `vegetation`：植被覆盖（0..1）；
  - `base_moisture` / `base_temperature`：种子导出的基线值，传播时作为
    局部松弛的锚点。

区块不可变意味着每次更新都产生新对象，读取者永远看到某个完整版本，不会
出现半更新。

## 3. 基线生成

`generate_base_chunk` 为每个区块生成传播前的基线：

- 高度 = `fbm(seed, x*0.05, z*0.05, octaves=terrain_octaves)`；
- 温度 = `base_temperature - latitude_factor*|z| - temperature_lapse*max(0, height-sea_level) + (noise-0.5)*6 + params.temperature_offset`；
- 湿度基线 = `noise*0.5 + 0.35 + params.moisture_offset`，海洋单元直接
  置为 1.0；
- 植被从 0 开始，在传播中生长。

地形高度只依赖种子，与区域参数无关，保证相邻区块的地形永远不会矛盾。

## 4. 跨区块传播

传播（`propagate`）采用**同步雅可比迭代**（synchronous Jacobi iteration）：

- 每一轮开始时快照上一轮的全部区块（含相邻区块的单元）；
- 每个单元依据快照中的邻居（可跨越区块接缝）计算下一轮的值；
- 一轮结束后整体切换到新一代区块。

因为每一轮都读取上一轮的快照，轮内不存在读写依赖环，所以无论风场是否
有旋、区块链有多长，都不会死锁。

### 4.1 湿度

- 平流：`moisture += moisture_advection * (upwind.moisture - moisture)`，
  上风单元由 `wind_dx / wind_dz` 决定；
- 扩散：与四邻单元做 `moisture_diffusion` 比例的均衡；
- 海洋：以 `ocean_evaporation` 速率向 1.0 松弛；
- 陆地：以 `groundwater_recharge` 速率向基线湿度松弛（地下水），并因
  地形抬升按 `rain_shadow` 比例流失（地形雨）。

### 4.2 温度

- 与四邻做 `temperature_diffusion` 比例的均衡；
- 以 `temperature_equilibration` 速率向基线温度松弛（气候由地理决定，
  横向扩散只是平滑接缝）。

### 4.3 植被

- 与四邻做 `vegetation_spread` 比例的均衡（传播）；
- 以 `vegetation_growth` 速率向当地气候潜势生长。潜势由温度与湿度共同
  决定（温度低于 5°C 或湿度低于 0.2 时植被无法生长），并受区域
  `fertility` 参数缩放。

### 4.4 收敛与取整

- 收敛条件：一轮中所有单元所有字段的最大变化量
  `max_delta < convergence_epsilon`（默认 1e-12）；
- 最大轮数：`max_propagation_rounds`（默认 300），作为安全上限。系统是
  压缩映射，正常情况下远在达到上限前收敛；
- 提交前把字段按 `field_decimals`（默认 6）位小数取整。取整使得局部
  变更后远场的微小扰动被确定性地舍入为相同值，从而保证：
  - 增量重算与全量重建逐格一致；
  - 未受影响的区块内容不变，对象身份得以保留（不被改写）。

## 5. 增量重算

`recompute(changes)` 只对指定区块用新参数重新生成基线，然后对**整个
已加载世界**做一次传播，最后只提交内容发生变化的区块（按单元内容逐格
比较，相同则保留原对象）。

由于传播是压缩映射，局部扰动随距离指数衰减，加上提交前的确定性取整，
远离变更点的区块最终与全量重建完全一致，且对象身份不变。

## 6. 并发模型

- 区块不可变 + 引用交换：读取者在任何时刻看到的都是某个完整版本；
- `_commit_lock`：串行化提交与快照捕获；
- `_generation_lock`：串行化整次生成/重算操作，避免并发请求各自传播
  后交错提交而漏掉跨区域接缝；
- 区块级锁：保护单个区块的读取；
- 耗时的基线生成（可用 `worker_threads` 并行）与传播在私有工作副本上
  进行，不共享可变状态。

## 7. 快照与版本

- `create_snapshot`：捕获当前世界为一个**已提交**快照（不可变，可回退）；
- `begin_snapshot`：创建**未完成**（pending）快照，状态与已提交快照可
  区分；`commit_snapshot` 提交，`abort_snapshot` 中止；
- `rollback`：恢复某个已提交快照的区块图。回退后继续生成与直接在该
  版本上生成得到一致结果。

## 8. 取消与超时

- `CancelToken`：线程安全的取消令牌，在每轮传播之间与每个区块生成之间
  检查；
- `timeout`：基于单调时钟的截止时间；
- 取消或超时发生在提交之前，因此**不留下任何部分写入**；重新触发后
  结果仍满足一致性与可复现要求。

## 9. API

`api.py` 提供 FastAPI 接口：创建世界、生成区域、增量重算、读取区块、
快照与回退、操作取消等。耗时操作在后台线程执行，通过操作句柄查询
状态。详见 `README.md` 与 `docs/config.md`。
